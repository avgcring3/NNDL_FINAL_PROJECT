NNDL Capstone Project

RideFlow NN

Нейросетевой прогноз спроса на такси и объяснимая оценка будущей стоимости поездки.

Problem Statement

  • Спрос меняется по зоне и часу.
  • Водители простаивают в тихих зонах, пока в других не хватает машин.
  • Статические средние не учитывают пики, погоду и локальные паттерны.

Product

Для оператора

14-дневный прогноз спроса по 12 зонам.

Для пассажира

Оценка будущей цены по адресу, дате и времени.

Explainability

Demand, weather и traffic/time coefficients.

One-click demo

START_RIDEFLOW.bat

Data

  • 60 дней hourly demand.
  • 12 московских зон.
  • 17 280 строк и 16 704 sliding-window samples.
  • Synthetic operational-style demo; adapters для real CSV и NYC TLC.

Prediction Task

[demand(t-47), ..., demand(t)] → demand(t+1)

  • 48-hour lookback.
  • Zone ID as contextual embedding.
  • Chronological train/validation/test split.

Transformer Architecture

  • Value projection 1 → 32.
  • Zone embedding + sinusoidal positional encoding.
  • Transformer Encoder, 4 attention heads, GELU, dropout.
  • Residual forecast head.

Custom Loss

Weighted MAE сильнее штрафует ошибки на targets выше 75-го перцентиля спроса.

mean(weight(target) × |prediction − target|)

Explainable Fare

Final fare = Base fare × Demand × Weather × Traffic/Time

  • Transformer forecast → demand coefficient.
  • Open-Meteo/wttr.in → weather coefficient.
  • OSRM route + time patterns → traffic/time coefficient.

KPI & Business Impact

  • Primary metric: test MAE.
  • Operational metric: Peak MAE и underforecast rate.
  • Меньше idle time и пропущенных поездок.
  • Короче ожидание пассажира.

Limitations

  • Текущий Moscow demand dataset synthetic.
  • Нет публичного официального Yandex Go price API.
  • Для production нужны реальные trip logs и live traffic.

Conclusion

RideFlow NN демонстрирует полный neural-network workflow: data pipeline, sliding windows, Transformer, custom loss, baselines, time-based validation, metrics и рабочий бизнес-интерфейс.
